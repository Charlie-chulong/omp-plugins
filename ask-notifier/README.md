# OMP 询问提醒

0.4.2：可选的 Windows x64 插件。OMP 等待用户回答问题时，通过 QQ 将会话名、完整问题和全部选项发送到自己的手机、Pad，或两个设备。收到后回 OMP 原会话回答；插件不读取 QQ 回复，也不代答。

手机和 Pad 统一使用 QQ 手动发送的普通消息属性结构，修复 Pad 消息能收到但没有声音、弹窗的问题。个人气泡等装饰值使用默认值。发送走原生后台接口，不移动鼠标、不输入键盘、不操作剪贴板或切换聊天窗口。

## 从源码安装

需要 OMP Desktop 0.7.0 兼容插件宿主、支持 `node:sqlite` 的 Node.js 22.5 或更新版本，以及 Windows x64 Python 3.11 或更新版本。推荐 Python 3.13；Python 依赖固定为 `psutil==7.2.2`。

仓库不包含 Python 运行时、构建后的 `dist/`、本地状态库或聊天记录。在本目录安装构建依赖并准备插件专用 Python 环境：

```powershell
npm ci --ignore-scripts --legacy-peer-deps
npm run build
node scripts/prepare-runtime.mjs --python "C:\path\to\python.exe"
```

准备脚本仅在 `.runtime/python` 内创建环境、安装依赖，不修改系统 Python，也不连接 QQ。也可以通过 `OMP_QQ_NOTIFIER_PYTHON` 指定已安装所需依赖的 Python 绝对路径。旧 `OMP_WECHAT_NOTIFIER_PYTHON` 不再读取，升级时需更新变量名。完整分发包可以另行包含 `runtime/python`；`准备提醒.cmd` 用于该类自带运行时的分发包。

在 OMP 插件管理中从本地目录安装本文件所在文件夹，启用 **OMP 询问提醒** 并授予 `agents.events`。这个插件单独构建和按文件夹安装，不修改 Desktop 的内置插件工作区清单。

## 升级与选择接收设备

0.4.0 起移除微信发送链路、设置展示、原生桥和构建配置，不再连接微信。包名 `omp-wechat-ask-notifier`、插件 ID/RPC 前缀 `wechat-ask-notifier` 和原状态目录保留，用于原安装升级。

升级前先停用插件。若更换安装目录或更新原生 DLL，请正常退出 QQ 并重新打开；只关聊天窗口到托盘不算退出。QQ 中的原生桥会驻留至 QQ 进程正常结束，不允许同时加载其他路径的同名桥。本次同目录脚本更新不更换 DLL，后台会刷新自身脚本缓存，不需要强制结束 QQ。

打开设置 → **OMP 询问提醒**，选择接收设备并开启自动提醒：

| 选项 | 提醒提交目标 |
| --- | --- |
| 仅手机 | QQ 内置“我的手机” |
| 仅 Pad | QQ 内置“我的 Pad” |
| 手机和 Pad | 两个设备通道各一份完整提醒 |

新安装默认关闭自动提醒、选择“仅手机”。升级保留已有开关和设备选择；从只支持手机的旧版升级时默认“仅手机”。选择自动保存，重启后保留；关闭自动提醒不清除选择。修改只影响之后新入队的提醒，不改变在途提醒，也不向新设备补发旧问题。

**发送测试提醒** 使用点击时已保存的设备选择。请在所选设备 QQ 的“我的电脑”中核对固定测试问题与两个选项，并确认提示音和弹窗；测试不创建或回答真实 OMP 问题。

## QQ 登录与退出

- QQ 已登录：核对当前账号后直接后台发送。
- QQ 未登录：尝试打开官方 QQ，最多等待 60 秒自动登录；不代输密码或扫码。
- 未安装、登录超时、多个已登录账号、接口不兼容或检查异常：跳过并显示具体原因，不猜选账号，不把检查失败当作未登录，也不回退到前台操作。
- 只正常退出本次由插件启动并核对身份的临时 QQ。所选设备的全部分段、当前已排队问题都确认提交后才允许退出；原本打开的 QQ 保持打开。
- 单端失败、结果未知、部分分段已提交后取消或退出无法确认时，保留 QQ 供核对，不强制结束。关闭插件只断开后台连接，不退出原有 QQ；载入的 DLL 保留至该 QQ 正常退出。

自研 DLL 通过 Node-API C ABI 在 QQ 主线程接入现有会话，不依赖 LLBot、PMHQ 或 NapCat。两个设备使用不同的内置 Dataline 地址，不搜索同名联系人，不允许配置任意好友或群。无法定位或提交 Pad 时显示原因，不改发手机。

兼容性依据实际后台接口、登录状态和账号/进程身份核验，不以版本号单独放行或拒绝。设备在线列表不是送达回执；离线设备是否随后收到由 QQ 决定，插件不增加补发队列。

## 分设备结果与去重

设置页分别显示手机和 Pad 的结果。“手机已提交、Pad 失败”显示为部分提交，不重复发送手机那份。每个设备、每段消息有独立请求标识，且与目标和内容绑定；相同标识不能改投另一设备。

**已提交只表示 QQ 接受发送请求。** 结果未知时到对应设备核对，插件不会自动重试。未知结果封锁当前发送连接代次；重启后新的问题仍可提醒，旧未知请求不重发。不要通过删除状态库重发。

状态保存在 `%LOCALAPPDATA%\OMP\wechat-ask-notifier\<安装实例>\`。升级保留开关、去重身份和原提交日志；旧版最近一次原始快照另行保留，新界面仅展示迁移出的 QQ 设备结果。上次进程尚未提交的排队记录不会重放。

## 提醒范围与隐私

- 支持当前 daemon 可见的普通 `ask`、`select`、`confirm` 问答，保留完整问题、全部选项、说明、预览、推荐和多选标记。
- 长内容按 UTF-8 安全分段，每段最多 4094 字节，带同一提醒标识和段号；双端分别收到完整分段。
- 自由输入、编辑器及明确标记为敏感的问题，仅提示回 OMP 查看，不转发其标题、正文、默认值或选项。
- 发送前再次核对问题仍待回答；已回答、撤回、归档或关闭提醒时停止排队和剩余提交。已经交给 QQ 的消息无法保证撤回。
- 同一待答请求跨重载去重；不同会话的同名请求独立。工具审批、计划审批、内部会话及其他远程 daemon 不在提醒范围。
- 状态库不保存问题正文或答案。状态库、聊天内容、原生探针记录和本地凭据不应提交到仓库。

## 开发与验证

```powershell
npm test
& "C:\path\to\python.exe" -I -B -m unittest discover -s tests -p test_qq_worker.py -v
```

测试使用临时目录和隔离夹具，不连接真实 QQ，也不发送消息。回归覆盖三种设备选择、分段、取消、旧数据库迁移及回滚、目标/正文/账号冲突、迟到结果、重启去重和临时 QQ 退出保护。

0.4.2 已在官方 QQ 9.9.37-54395 实测：手机和 Pad 各收到一份新测试提醒，用户确认两端提示音、弹窗均正常。0.4.0 曾出现 Pad 静默收到消息，0.4.1 先补齐 Pad 普通属性，0.4.2 将手机统一到相同结构。该版本号是实测记录，不是兼容性白名单。

设置页的三种选择、自动保存、刷新后保留及分设备失败/未知结果展示已在隔离页面验证；独立分发包已在 OMP Desktop 内置 Node `v24.0.0-pre` 中加载并核验管理模式和 RPC 边界。

QQ 原生桥保留源码和预编译 Windows x64 DLL。只在修改原生源码时需要 Visual Studio x64 C++ Build Tools：

```powershell
npm run build:qq-native
```

构建入口为 `scripts/build-qq-native.ps1`。本次设备路由和消息属性更新不改变 C++ 协议或 DLL。
