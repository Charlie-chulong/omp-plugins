# QQ 与微信询问提醒

可选的 Windows x64 插件：OMP 等待用户回答问题时，将会话名、完整问题和选项发送到 QQ 内置「我的手机」及微信「文件传输助手」。收到提醒后仍需回 OMP 原会话回答；聊天软件中的回复不会提交到 OMP，插件不会代答。

QQ 和微信都使用本机原生后台接口，发送不移动鼠标、不输入键盘、不操作剪贴板或切换聊天窗口。QQ 不限定精确版本号，兼容性由实际接口、登录状态和会话账号绑定决定。

## 从源码安装

需要 OMP Desktop 0.7.0 兼容插件宿主、支持 `node:sqlite` 的 Node.js 22.5 或更新版本，以及 Windows x64 Python 3.11 或更新版本。推荐 Python 3.13；Python 依赖固定为 `psutil==7.2.2`。

本仓库不包含 Python 运行时、构建后的 `dist/`、本地状态库或聊天记录。先在本目录安装构建依赖并准备插件专用 Python 环境：

```powershell
npm install --ignore-scripts --legacy-peer-deps
npm run build
node scripts/prepare-runtime.mjs --python "C:\path\to\python.exe"
```

准备脚本仅在 `.runtime/python` 内创建环境、安装依赖，不修改系统 Python，也不连接 QQ 或微信。也可以通过 `OMP_WECHAT_NOTIFIER_PYTHON` 指定已安装所需依赖的 Python 绝对路径。完整分发包可以另行包含 `runtime/python`；`准备提醒.cmd` 用于该类自带运行时的分发包。

在 OMP 插件管理中从本地目录安装本文件所在文件夹，启用插件并授予 `agents.events`。随后进入「QQ 与微信询问提醒」设置页，开启默认关闭的「自动提醒」。这个插件单独构建和按文件夹安装，不修改 Desktop 的内置插件工作区清单。

保持现有包名 `omp-wechat-ask-notifier`、插件 ID 和 RPC 前缀 `wechat-ask-notifier`，升级无需更换状态命名空间。

## 提醒通道

| 登录情况 | 行为 |
| --- | --- |
| QQ、微信都已登录 | 两个通道同时发送 |
| 仅 QQ 已登录 | 只发 QQ「我的手机」 |
| 仅微信已登录 | 只发微信「文件传输助手」 |
| 两个都明确未登录 | 临时打开官方 QQ，最多等待 60 秒自动登录后发送 |

不会代输密码或扫码。未安装、登录超时、状态检查异常或账号不明确时，显示原因并跳过；不能把检查失败当成「未登录」来自动启动客户端。

只有本插件临时启动并核对了进程身份、当前批次所有分段均已提交的 QQ 才会正常退出。原先已打开的 QQ 保持打开；发送失败、部分取消、结果未知或正常退出无法确认时保留客户端，不强制终止。官方 QQ 启动时仍由其自行显示窗口和完成登录，发送步骤本身不操作界面。

## 原生接口与兼容性

- **QQ**：自研 DLL 通过稳定的 Node-API C ABI 在 QQ 主线程接入现有会话，固定使用内置手机设备通道，不使用同名联系人，不依赖 LLBot、PMHQ 或 NapCat。QQ 版本号仅用于显示与诊断；实际接口缺失、多账号或会话账号绑定无法证明时跳过，不回退鼠标操作，也不自动降级为普通「发给自己」消息。
- **微信**：向经过进程、账号和构建指纹核验的客户端加载原生发送桥，目标固定为 `filehelper`。仅接受 `native/engine/profiles.json` 中的构建指纹；微信更新后可能需要适配。已经被其他原生发送宿主占用的微信进程会被拒绝，不应将多个发送宿主连接到同一进程。
- 关闭插件会断开连接并撤销后续工作，不等于撤回已进入客户端的消息。为避免卸载运行中代码，QQ 中的 DLL 保留到该 QQ 正常退出。

已在官方 QQ 9.9.37-54395 验证自动启动、登录、后台文本提交、手机端收到和临时 QQ 主/子进程正常退出；该版本号是实测记录，不是白名单。微信发送端完成离线协议与状态机验证，独立目标机上的真实文件传输助手发送仍需验收。

## 去重、敏感内容与结果未知

- 支持当前 daemon 可见的普通 `ask`、`select`、`confirm` 请求，保留说明、预览、推荐和多选标记。长内容按 UTF-8 安全分段，每段最多 4094 字节。
- 自由输入、编辑器和显式敏感请求仅发送「请回 OMP 查看并回答」提示，不转发其正文、默认值或选项。
- 发送前重新核对请求是否仍待回答。关闭期间、离线跳过、重载前未提交的旧提醒不会之后补发。
- 同一请求去重，两个通道独立记录状态；一个通道失败不阻止另一个完成其分段。
- 在不可逆提交前持久化发送意图；超时、断管或回包不明确时保留 `unknown`，不自动重发。不要删除状态库来绕过去重或未知结果。
- 工具执行审批、计划审批、内部会话和其他远程 daemon 不在提醒范围。

「已提交」只代表客户端接口提交结果，不代表手机收到或已读。请在设置页发送一次测试提醒，并在手机端核对。状态和去重记录位于 `%LOCALAPPDATA%\OMP\wechat-ask-notifier\<安装实例>\`，这些数据应留在本机，不提交到仓库。

## 开发与验证

准备好 Python 后运行：

```powershell
npm test
```

测试使用临时目录和隔离夹具，不启动或连接真实 QQ、微信，也不发送消息。Windows 下的测试同时运行 Python 日志、进程身份和原生清单检查；非 Windows 平台跳过客户端相关用例。

两套原生桥均包含源码和预编译 Windows x64 DLL。修改原生源码后，需要 Visual Studio x64 C++ Build Tools：

```powershell
npm run build:qq-native
npm run build:wechat-native
```

QQ 构建入口为 `scripts/build-qq-native.ps1`，微信入口为 `native/engine/build.ps1`。微信构建更新 `native/runtime/current.json` 中的相对路径、源码摘要和 DLL 摘要；载入时会再次校验。构建本身不连接客户端。
